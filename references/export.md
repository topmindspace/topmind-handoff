# 导出工作流（Export）

目标：把本工具里关于用户的上下文，收敛成一份符合 `spec.md` 的交接包。
全程只读源，不写源文件；唯一的写出是交接包本身。

## 步骤

### 1. 采集（Gather）

按所在工具的来源清单读（各工具来源见 `tool-adapters.md`）：

- 用户画像文件（如 `USER.md`、`profile.md`）
- 记忆文件（如 `MEMORY.md`、按日归档的 memory 日志）
- 工作区规约（如 `AGENTS.md`）、技能清单（各 `SKILL.md` 的 frontmatter）
- 目标/待办（如 `GOAL.md`）
- 最近 1~3 个月的对话摘要（只取结论，不取原文流水账）

采集原则：**宁缺勿滥**。一次会话的闲聊不进包；重复出现 ≥2 次的偏好才算"持久"。

### 2. 分类（Classify）

每条信息进五桶：

| 桶 | 定义 | 例子 |
|---|---|---|
| 持久偏好 | 长期稳定、换工具也成立 | "全程中文""去 AI 味写作" |
| 当前状态 | 现在成立、以后会变 | 技能版本号、项目进度 |
| 项目待办 | 未完成的事 | "X 长文未发布""Claude 注册卡在短信验证" |
| 历史经验 | 踩过的坑，写教训 | "文件名排序 ≠ 文档顺序导致配图错位" |
| 敏感丢弃 | 见 `privacy.md`，直接丢弃 | 密码、token、身份证号 |

自定义节（如上次包里的 `## 7.`）：本地有对应内容的，一并带出并保留原标题；
没有对应内容的，不凭空保留——以本地事实为准，不以"上次有"为准。

### 3. 裁决冲突（Resolve）

- 同一事实多个版本 → **以最新日期的证据为准**，旧版本不进包。
- 日期不明 → 保留措辞更谨慎的版本，或标"（未核实）"。
- 用户亲口纠正过的内容，优先级高于一切推断。

### 4. 脱敏（Sanitize）

1. 跑一遍 `privacy.md` 的"永不携带"清单做硬拦截（正则见下）。
2. 联系方式类（邮箱/电话/地址）默认删除，除非用户明确要求保留。
3. 路径里的用户名泛化为 `~`（如 `/Users/zhangsan/...` → `~/...`）。
4. 他人（家人、同事、朋友）的隐私信息删除或泛化为角色（"家人"）。
5. **人工确认**：把"删了什么、泛化了什么"列成清单给用户看，用户点头再定稿。

常用硬拦截正则（大小写不敏感）：

```
api[_-]?key|secret|token|password|passwd|pwd
bearer\s+[A-Za-z0-9\-._~+/]+
sk-[A-Za-z0-9]{16,}|ghp_[A-Za-z0-9]{16,}|xox[bap]-[A-Za-z0-9-]{10,}
\d{15,19}                       # 疑似银行卡号（结合上下文人工复核）
(身份证|id[_\s-]?card).{0,10}\d{17}[\dXx]
```

> 注意：正则只是第一道网，**人工复核是必须的**。误杀（删多了）比漏网好，
> 漏网的代价是隐私泄露。

### 5. 落盘交付（Package）

- 按 `spec.md` 写文件，文件名 `<称呼>-handoff-YYYYMMDD.md`。
- 从 `assets/handoff-template.md` 起稿，逐节填充。
- 回执给用户：文件路径 + 统计（六节各几条、本次新增/更新/删除几条、
  脱敏删了几条、哪几条标了"未核实"）。

## 定期重跑

用户说"更新一下交接手册"时：重跑 1~5 步，以**上一次的交接包为基线**做 diff，
回执只讲变化（新增/更新/删除），不复述全文。
