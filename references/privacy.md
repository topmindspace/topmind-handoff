# 隐私保护（Privacy）

交接包是"一次给全"的画像文件：**拿到文件的人就拿到了画像**。
本节是硬线，导出和导入都要执行。

## 永不携带（Never carry）

以下类别**永远**不进交接包，发现即删，不问用户：

- 密码、API key、token、secret、会话 cookie、私钥
- 一次性验证码、登录链接、密码重置链接
- 身份证号、护照号、社保号等政府证件号
- 银行卡号、支付账号
- 精确家庭住址（精确到门牌号）
- 他人的隐私信息（家人/同事/朋友的联系方式、隐私细节）
- 私有文件的原文内容（只允许一句话引用，不贴全文）

## 默认不携带（Opt-in 才进）

以下默认删除，**用户明确要求**才保留：

- 邮箱、手机号
- 城市级地址
- 真实姓名（可用网名/称呼代替）
- 工作单位、职位（可用"某互联网公司"泛化）

## 脱敏手法

| 手法 | 用法 | 例子 |
|---|---|---|
| 删除 | 高敏信息直接不要 | 删掉整条含 token 的记忆 |
| 泛化 | 降精度保留有用部分 | "北京市朝阳区某小区 3 号楼" → "北京" |
| 角色化 | 他人信息转角色 | "我老婆电话 138…" → "家人" |
| 引用不存值 | 需要时只记"有这个东西" | "GitHub 推送用一次性 PAT（用完即弃）"——记机制，不记 PAT 本身 |

## 路径与标识泛化

- 本地路径里的用户名 → `~`：`/Users/zhangsan/docs` → `~/docs`。
- 机器名、内网 IP、设备序列号 → 删除或泛化。
- 示例必须用占位符：`user@example.com`、`138-0000-0000`。

## 分享警告

导出完成后必须告诉用户一句话：

> "这份交接包包含你的画像信息，拿到文件的人就能看到。
> 只发给你自己的工具，不要公开分享、不要贴到公开 issue/论坛。"

## 导入侧复查

别家工具导出的包**可能没做脱敏**。导入时按同样清单再扫一遍，
把不该进本地记忆的东西拦在确认环节（见 `import.md` 反投毒规则）。

## 为什么是"人工确认"而不是全自动

记忆投毒和密钥泄露的公开事故（见仓库 README 的背景）证明：
正则 + 模型判断都可能漏。**导出前的人工 review 是最后一道门**，
不能省。流程上：技能列出"删了什么、泛化了什么"的清单，
用户点头才定稿。

## 第 9 节与同级资料包

「永不携带」和「默认不携带」同样适用于第 9 节正文，以及同级
`<主文件名>-assets/` 目录或 zip。那里不是第二份密钥存放处。

- 云端只记位置（remote 或网盘链接），不把大文件或数据集的内容嵌进包。
- 建议落点用相对路径，如 `./docs/`。本地路径里的用户名写成 `~`，不写绝对家目录。
- 资料包里发现 token、证件号、精确住址、他人隐私：整份不进包，并写进脱敏清单。

## origin_id 与交接云端

- `cloud_repo` 写成 `owner/name` 可以进包。仓库 URL 可以出现在说明里。不要写 PAT、token、cookie、私钥，也不要让用户把 token 贴进对话。技能和包都不保存这些凭据。没有现成的 git / `gh` 凭据就停下，不改口索要 token。
- `origin_id` 不是秘密，但三段（`工具-账号标识-范围`）里不得有凭据。账号标识用 handle 或用户认得的登录名。邮箱只有用户明确要求保留才放进 id。
- 只接受私有仓库。看起来公开：不推、不拉、不删。
- 清理只作用于已配置的私有仓库、已配置的 `cloud_path`、以及其中同一个 `origin_id` 的旧包。不删除其他来源。不碰第 9 节的项目仓库、家目录或其他无关路径。
